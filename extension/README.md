# 브라우저 확장 (시험판)

카카오맵 장소 페이지에서, 사용자가 화면에 펼친 후기만으로 리뷰어 편차를 계산해 오른쪽 아래에 보여 준다.
배포하지 않았다. 개발자 모드로 직접 불러와서 쓴다.

## 목차

1. 보여 주는 것
2. 하지 않는 것
3. 파일
4. 확인 방법

## 1. 보여 주는 것

주 숫자는 전체 편차다. 리뷰어가 평소 주는 별점보다 이 가게에 얼마나 더 주었는지의 평균이고, 평소 4.8점
이상을 주는 리뷰어는 뺀다. 맛 점수가 아니다. 본문 없는 후기도 들어가서, 88곳에서 LLM 레이블로 잰 맛 편차보다
평균 0.23 낮았다(성동 26곳에서는 0.28).

참고값은 규칙 분류기 v2로 맛을 말한 후기만 남긴 편차다. 전체 편차가 이 값의 95% 구간 밖에 있을 때만 띄운다.
마포 88곳에서 이 조건을 정했고 성동 26곳에서 확인했다. 조건이 걸린 가게에서 LLM 레이블 기준 오차는
전체 편차가 0.40과 0.44, 참고값이 0.09와 0.18이었다. 규칙 분류기는 후기 단위로는 10에서 15퍼센트를 잘못
거르므로 참고값으로만 둔다. v3가 아니라 v2를 쓰는 이유는 METHOD.md 5절에 있다.

쓸 수 있는 후기가 15건 미만이면 판단 보류로 두고, 몇 건을 더 펼치면 되는지 어림해서 보여 준다.
마포 88곳을 최신 후기로 잘라 보면 20건(첫 화면)에서는 절반이 보류였고 40건에서는 22퍼센트였다.
후기 탭은 20건씩 불러오고, 목록을 끝까지 내리면 다음 20건을 부른다.

후기 정렬이 최신순일 때만 계산한다. 기본 정렬인 추천순은 긍정 후기를 앞에 세워서 표본이 기운다.

## 2. 하지 않는 것

요청을 새로 만들지 않는다. 페이지가 스스로 부른 후기 응답을 복사해 읽을 뿐이고, 다음 페이지는 사용자가
후기 목록을 아래로 내려야 불린다. 카카오맵 robots.txt 는 모든 자동 접근을 막고 있고, 확장이 스스로 페이지를 넘기면
수집기와 같은 일이 된다.

받은 후기는 그 탭의 메모리에만 있다. 저장하지 않고 어디에도 보내지 않는다. 권한을 요청하지 않는다.

## 3. 파일

| 파일 | 하는 일 |
|---|---|
| manifest.json | place.map.kakao.com 에서만 두 스크립트를 띄운다 |
| hook.js | 페이지 쪽에서 돈다. 후기 응답을 복사해 넘긴다 |
| panel.js | 받은 후기를 모아 계산하고 패널을 그린다 |
| core.js | 계산 핵심. normalize.py, label_rules.py v2, score.py 와 같은 값을 낸다 |
| rules_v2.js | 생성 파일. gen_rules.py 가 커밋 41666b4 의 label_rules.py 에서 정규식을 옮긴다 |
| parity.mjs | Python 과 대조. 수집 데이터가 있어야 돈다 |
| core.test.mjs | 데이터 없이 도는 테스트 |
| dev/harness.html | 카카오에 접속하지 않고 지어낸 응답으로 패널을 확인하는 페이지 |

## 4. 확인 방법

```
node --test extension/core.test.mjs
python3 extension/gen_rules.py
node extension/parity.mjs data/reviews.jsonl data/labels/rules_mapo_v2.jsonl
python3 -m http.server 8765 --directory extension
```

마지막 줄을 띄운 뒤 http://localhost:8765/dev/harness.html 을 연다.

10월 6일 대조 결과: 마포 8,084건과 성동 2,787건에서 편차, 레이블, 가게별 점추정과 표본 수가 Python 과 모두 같았다.
참고값을 띄우는 가게도 같았다(마포 12곳, 성동 3곳). 구간 끝값은 난수가 달라서 최대 0.05 차이가 난다.

10월 6일 실제 장소 페이지 하나에서 확인한 것(확장을 설치하지 않고 개발자 도구로 요청만 봤다).
장소 페이지는 iframe 이 아니라 최상위로 열린다. 후기 목록은 XHR 로 부르고 경로는 /places/tab/reviews/kakaomap/ 이다.
기본 정렬 값은 RECOMMENDED 이고, 최신순으로 바꾸면 LATEST 로 다시 부른다. 목록을 끝까지 내리면
previous_last_review_id 를 붙여 다음 20건을 부르고 정렬 값은 유지된다. 응답의 후기 20건 모두에 core.js 가 읽는
필드(review_id, star_rating, contents, 작성자 후기 수와 평균)가 있었다. 이어 부르는 응답에는 가게 단위 값(score_set)이 없다.

확장을 설치해서 패널이 실제로 뜨는지는 아직 보지 않았다.
