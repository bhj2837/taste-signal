# 브라우저 확장 (시험판)

카카오맵 장소 페이지에서, 사용자가 화면에 펼친 후기만으로 리뷰어 편차를 계산해 오른쪽 아래에 보여 준다.
배포하지 않았다. 개발자 모드로 직접 불러와서 쓴다.

## 목차

1. 보여 주는 것
2. 하지 않는 것
3. 파일
4. 확인 방법

## 1. 보여 주는 것

맨 위는 맛 티어다(S, A, B, C, D). 규칙 분류기 v2로 맛을 말한 후기만 남겨 리뷰어 편차를 내고, 그 값을 수집한
고깃집 77곳(서울 마포와 성동, 판단 보류 제외)의 기준 분포에 끼워 넣어 등급을 매긴다. 등급 규칙은 score.py 와
같다. 맛 편차 순으로 놓고, 다음 가게가 지금 묶음의 어느 가게보다든 차이 검정(z 1.96)으로 뚜렷이 낮으면 새
묶음을 연다. 같은 티어 안의 가게끼리는 우열을 말할 수 없다. 기준 분포 안에서 상위 몇 퍼센트인지도 함께 보인다.

기준 분포는 reference.js 이고 gen_reference.mjs 가 core.js 로 계산해 만든다. 가게마다 맛 편차, 그 표준오차,
후기 30개 이상 리뷰어만의 편차 세 숫자만 있다. 가게 이름, 식별자, 후기는 없다.

같은 114곳을 LLM 레이블로 매긴 등급과 비교하면, 둘 다 등급이 나온 66곳 중 43곳(65퍼센트)이 같은 티어였고
나머지 23곳은 한 칸 차이였다. 두 칸 이상 차이 난 가게는 없었다. 각 가게는 자기를 뺀 기준 분포에 끼워 넣었다.

그 아래 세 줄이 있다.

- 경험 많은 손님. 후기 30개 이상 쓴 리뷰어만의 편차(본문으로 거르지 않음)가 기준 분포에서 맛 편차와 25퍼센트
  이상 다른 위치에 있으면 "이보다 낮게 본다" 또는 "높게 본다"를 붙인다. 이런 계정은 만들기 비싸서 조작에 강하다.
- 일회성 계정. 후기 1개짜리 계정의 비율이 수집한 가게 중 상위 10퍼센트(29퍼센트 이상)이고 후기를 40건 이상
  펼쳤을 때만 붙인다. 맛 편차와 상관이 거의 없는 다른 축이다(마포 0.06, 성동 -0.06). 판정이 아니다.
- 전체 편차. 본문으로 거르지 않은 편차(천장 제외)다. 맛 외의 이유가 섞인다.

평소 4.8점 이상을 주는 리뷰어는 뺀다. 맛을 말한 후기가 15건 미만이면 판단 보류로 두고, 몇 건을 더 불러오면
되는지 어림해서 보여 준다. 후기 정렬이 최신순일 때만 계산한다. 기본 정렬인 유용한 순(RECOMMENDED)은 긍정 후기를
앞에 세워서 표본이 기운다.

이 지표들을 고른 근거(반분 신뢰도와 지표 사이 상관)는 METHOD.md 9절에 있다. 처음 판(0.1.0)은 전체 편차를 주 숫자로
쓰고 맛 편차는 조건부 참고값으로만 띄웠다.

## 2. 하지 않는 것

요청을 새로 만들지 않는다. 페이지가 스스로 부른 후기 응답을 복사해 읽을 뿐이고, 다음 페이지는 사용자가
후기 목록을 아래로 내려야 불린다. 카카오맵 robots.txt 는 모든 자동 접근을 막고 있고, 확장이 스스로 페이지를 넘기면
수집기와 같은 일이 된다.

받은 후기는 그 탭의 메모리에만 있다. 저장하지 않고 어디에도 보내지 않는다. 권한을 요청하지 않는다.

## 3. 파일

| 파일 | 하는 일 |
|---|---|
| manifest.json | place.map.kakao.com 에서만 두 스크립트를 띄운다 |
| hook.js | 페이지 쪽에서 돈다. 후기 응답을 복사해 넘긴다 |
| panel.js | 받은 후기를 모아 계산하고 패널을 그린다 |
| core.js | 계산 핵심. normalize.py, label_rules.py v2, score.py 와 같은 값을 낸다. 티어도 여기서 매긴다 |
| reference.js | 생성 파일. 기준 분포(가게 77곳의 숫자만) |
| gen_reference.mjs | reference.js 를 만든다. 수집 데이터가 있어야 돈다 |
| rules_v2.js | 생성 파일. gen_rules.py 가 커밋 41666b4 의 label_rules.py 에서 정규식을 옮긴다 |
| parity.mjs | Python 과 대조. 수집 데이터가 있어야 돈다 |
| core.test.mjs | 데이터 없이 도는 테스트 |
| dev/harness.html | 카카오에 접속하지 않고 지어낸 응답으로 패널을 확인하는 페이지 |

## 4. 확인 방법

```
node --test extension/core.test.mjs
python3 extension/gen_rules.py
node extension/parity.mjs data/reviews.jsonl data/labels/rules_mapo_v2.jsonl
node extension/gen_reference.mjs data/reviews.jsonl data/reviews_seongsu.jsonl
python3 -m http.server 8765 --directory extension
```

마지막 줄을 띄운 뒤 http://localhost:8765/dev/harness.html 을 연다.

10월 6일 대조 결과: 마포 8,084건과 성동 2,787건에서 편차, 레이블, 가게별 점추정과 표본 수가 Python 과 모두 같았다.
참고값을 띄우는 가게도 같았다(마포 12곳, 성동 3곳). 구간 끝값은 난수가 달라서 최대 0.05 차이가 난다.

10월 6일 실제 장소 페이지 하나에서 확인한 것(확장을 설치하지 않고 개발자 도구로 요청만 봤다).
장소 페이지는 iframe 이 아니라 최상위로 열린다. 후기 목록은 XHR 로 부르고 경로는 /places/tab/reviews/kakaomap/ 이다.
기본 정렬 값은 RECOMMENDED 이고, 최신순으로 바꾸면 LATEST 로 다시 부른다. 목록을 끝까지 내리면
previous_last_review_id 를 붙여 다음 20건을 부르고 정렬 값은 유지된다. 응답의 후기 20건 모두에 core.js 가 읽는
필드(review_id, star_rating, contents, 작성자 후기 수와 평균)가 있었다. 이어 부르는 응답에는 가게 단위 값(score_set)이 없다.

확장을 설치해서 패널이 실제로 뜨는지는 아직 보지 않았다.
